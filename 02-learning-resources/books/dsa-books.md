# DSA books — what each one is for

## 1. *Cracking the Coding Interview* — Gayle Laakmann McDowell

**Uploaded edition:** Sixth Edition, 2015  
**Publisher:** CareerCup  
**Best for:** interview problem-solving methodology, classic interview questions, hints, solution derivation and selected CS fundamentals.

### What to prioritise

- Introduction, Chapter VI — Big O (printed pp. 38–59).
- Introduction, Chapter VII — Technical Questions (printed pp. 60–81).
- Chapter 1 — Arrays and Strings (p. 88).
- Chapter 2 — Linked Lists (p. 92).
- Chapter 3 — Stacks and Queues (p. 96).
- Chapter 4 — Trees and Graphs (p. 100).
- Chapter 5 — Bit Manipulation (p. 112).
- Chapter 8 — Recursion and Dynamic Programming (p. 130).
- Chapter 10 — Sorting and Searching (p. 146).

Use Chapter 6 (Math and Logic Puzzles) selectively. Chapters 7 and 9 cover object-oriented design and system design/scalability; they are useful, but they are not a replacement for a dedicated modern system-design curriculum.

### How to work through its questions

1. Read the topic introduction.
2. Attempt a selected problem independently.
3. Use the hint section before reading the full solution if stuck.
4. Study the solution's reasoning and alternatives.
5. Close the book and derive the approach again.
6. Implement, test edge cases and explain complexity.
7. Add it to the revision tracker.
8. Reinforce the same concept using a different NeetCode / LeetCode problem.

Do not race to complete all 189 questions. Select for learning value and revisit difficult problems.

### Important limitation

This edition was published in 2015. Some interview context, examples and coverage may be dated. Its fundamentals and problem-solving techniques can still be useful, but it should not be the only preparation resource.

## 2. *Data Structures Using C* — Reema Thareja

**Uploaded edition:** Second Edition, 2014  
**Publisher:** Oxford University Press  
**Best for:** structured explanations of data structures, their operations, representations, applications and C implementations.

### Chapters most relevant to DSA

| Chapter | Printed start page | Use |
|---|---:|---|
| 2. Introduction to Data Structures and Algorithms | 43 | ADTs, operations, algorithm design and complexity |
| 3. Arrays | 66 | Array representation and operations |
| 4. Strings | 115 | Character arrays and string operations |
| 6. Linked Lists | 162 | Singly, doubly, circular and header lists |
| 7. Stacks | 219 | Stack operations, applications, recursion |
| 8. Queues | 253 | Queue operations and applications |
| 9. Trees | 279 | Tree types, binary trees and traversals |
| 10. Efficient Binary Trees | 298 | BSTs, AVL, red-black and splay trees |
| 11. Multi-way Search Trees | 344 | M-way, B/B+ trees, tries and 2-3 trees |
| 12. Heaps | 361 | Binary, binomial and Fibonacci heaps |
| 13. Graphs | 383 | Representations, traversals and applications |
| 14. Searching and Sorting | 424 | Search and sort algorithms |
| 15. Hashing and Collision | 464 | Hash functions and collision resolution |

Use Chapter 1 only if you need a C-language refresher. Chapter 5 (Structures and Unions) helps understand the C representations used in later data structures. Chapter 16 (Files and Their Organization) is supplementary rather than core interview DSA.

### How to use it if you code in C++

Read for the data-structure model, operation sequence, diagrams and complexity. Re-implement the ideas using modern C++ and STL where appropriate. Do not copy unsafe or obsolete C idioms into C++ without understanding them.

## 3. How the two books complement each other

- **Reema Thareja:** build a systematic understanding of what a structure is, how it is represented and how its operations work.
- **CTCI:** practise applying concepts to interview-style problems and learn how to reason from a prompt toward an algorithm.
- **NeetCode 150:** broaden and reinforce pattern-based problem-solving with a structured current practice list.

The books overlap in some topics. That is useful when the second explanation clarifies a concept, but avoid reading the same introductory material repeatedly instead of practising.
