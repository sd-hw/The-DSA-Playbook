# Revision schedule

A simple schedule to make revision deliberate.

| Interval | What to test | What to do if you struggle |
|---|---|---|
| Same day | Explain the key idea without notes | Re-read your own summary, then explain again |
| Day 1 | Re-derive the approach | Review one hint, then retry |
| Day 3 | Implement from a blank file | Study the missed step and schedule tomorrow |
| Day 7 | Solve and explain edge cases | Add a similar problem to practise transfer |
| Day 14 | Recall the pattern in a mixed set | Move the problem back to a shorter interval |
| Day 30 | Long-term retention check | Relearn the concept and restart the cycle |

## A revision session

1. Select 3–5 problems due for revision.
2. Hide previous code and notes.
3. State the problem's core idea.
4. Derive the approach and complexity.
5. Implement or outline the solution.
6. Mark performance and choose the next date.

A short, focused session is better than passively rereading dozens of solutions.
