# How to revise a DSA problem

A revision attempt should test recall, not recognition.

## Before opening your old solution

1. Read only the problem statement.
2. State the input constraints.
3. Work through an example.
4. Derive the approach from scratch.
5. Explain the invariant or key observation.
6. State time and space complexity.
7. Implement or outline the solution.
8. Test edge cases.

## After the attempt

Compare your reasoning with your previous notes:
- Did you remember the key observation?
- Did you choose the right data structure?
- Did you miss an edge case?
- Did you understand why the algorithm is correct?
- Did you make the same mistake again?

Update the tracker and choose the next interval.

## Avoid passive revision

Simply rereading code, watching an explanation again or recognising a familiar solution is not the same as independently deriving it.
